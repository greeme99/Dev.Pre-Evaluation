## 1. 구현 목표와 첫 수직 슬라이스

최종 목표는 Windows 로컬 환경에서 Excel 지식 구축부터 PDF/DXF 검사, 근거 확인과 결과 내보내기까지 한 흐름으로 동작하는 제품이다. 첫 수직 슬라이스 M0는 빈 앱 골격이 아니라 다음을 실제로 증명한다.

1. Windows에서 FastAPI와 React 앱을 실행한다.
2. 합성 PDF 한 건을 안전하게 업로드한다.
3. 영속 작업을 생성하고 재시작 후 상태를 복구한다.
4. 합성 규칙 한 건으로 Finding을 만든다.
5. 결과를 웹 화면에 표시한다.

AI·OCR·벡터 검색 없이도 이 슬라이스가 통과해야 이후 기능을 추가한다.

## 2. 스택과 버전 정책

| 영역 | 선택 | 기준 |
| --- | --- | --- |
| 런타임 | Python 3.12.x, Node.js 22 LTS, pnpm 10.x | Windows 지원과 장기 유지보수 |
| API | FastAPI, Pydantic 2 | 명시적 계약과 OpenAPI 생성 |
| UI | React 19, TypeScript 5, Vite | 로컬 정적 배포와 타입 안전성 |
| 메타데이터 | SQLite, SQLAlchemy 2, Alembic | 단일 사용자·무서버 운영 |
| 키워드·벡터 | SQLite FTS5, qdrant-client local mode | 설치 부담 없는 hybrid 검색 |
| 문서/CAD | openpyxl+lxml, PyMuPDF, ezdxf | 좌표·구조 추출과 원본 추적 |
| 모델 | ONNX Runtime, llama.cpp | CPU 기본과 선택 GPU 가속 |
| 테스트 | pytest, Vitest, Playwright | 단위부터 Windows E2E까지 |
| 패키징 | PyInstaller, Inno Setup | Docker 없는 설치 프로그램 |

- 직접 의존성은 잠금 파일에 고정하고 자동 major upgrade를 허용하지 않는다.
- 모델은 `models.json`에 URL, revision, SHA-256, 크기, 라이선스와 최소 사양을 고정한다.
- CPU 기본 후보는 PaddleOCR 한국어 mobile, `multilingual-e5-small` ONNX, CLIP ViT-B/32 ONNX, 선택형 Qwen3-4B-Instruct GGUF Q4_K_M다.
- 후보 모델은 M3 Gate의 골든셋과 라이선스 검토를 통과해야 기본 manifest가 된다.

## 3. 아키텍처 경계

```text
UI/API → Analysis Pipeline → Domain
             │                  │
             ├─ Drawing ports ─ PDF/DXF adapters
             ├─ Rule port ───── deterministic engine
             ├─ Retrieval ports  FTS/Qdrant/Pixel
             ├─ Model ports ──── OCR/embedding/generation/OpenAI
             └─ Storage ports ── SQLite/files/credentials
```

- Domain은 FastAPI, SQLAlchemy, 모델 SDK에 의존하지 않는다.
- 어댑터는 공통 타입 `DrawingDocument`, `Finding`, `Evidence`, `ImprovementSuggestion`을 반환한다.
- 분석 단계는 validate, extract, rules, retrieve, suggest, export_ready이며 각 완료점을 DB에 기록한다.
- OpenAI 공급자는 기본 dependency graph에 등록하지 않고 설정·동의가 있을 때만 생성한다.

## 4. 목표 저장소 구조

```text
apps/api/src/dev_pre_review/

  retrieval/ models/ analysis/ export/ evaluation/
```

각 폴더는 공개 포트를 작은 `contracts.py` 또는 package entry point로 노출하고 구현 세부사항을 다른 기능이 직접 import하지 않게 한다.

## 5. 데이터·API·작업 접근

- SQLite는 업무 엔터티와 작업 체크포인트의 권위 원장이다.
- 원본·타일·내보내기는 `%LOCALAPPDATA%\DevPreReview` 아래 해시 기반 경로에 원자적으로 쓴다.
- FTS5와 Qdrant는 재구축 가능한 인덱스이며 소스 레코드와 index version을 payload에 포함한다.
- OpenAPI에서 TypeScript 계약을 생성하고 CI에서 drift를 차단한다.
- 상태 변경 API는 idempotency key와 expected version으로 중복과 충돌을 막는다.
- 작업은 PC당 하나만 실행하고 FIFO 대기하며 취소는 안전한 단계 경계에서 완료한다.

## 6. 보안·개인정보·공급망

- `127.0.0.1:17841` 전용 바인딩과 단일 인스턴스 health token을 사용한다.
- API 키는 Windows Credential Manager, 백업은 Argon2id+AES-256-GCM을 사용한다.
- 로그 필터는 원문, API 키, 절대 경로, 외부 payload를 제거한다.
- 실제 도면은 저장소·CI artifact·오류 추적 서비스에 올리지 않는다.
- SBOM과 dependency/license scan을 릴리스마다 생성한다.
- 모델 다운로드는 해시와 라이선스 동의 검증 뒤 활성화한다.
- OpenAI 전송은 RULE-007과 ConsentRecord를 만족해야 하며 실패 시 로컬 결과를 보존한다.

## 7. UI 구현 원칙

- [UI 설계 명세서](05.UI-설계-명세서.md)의 토큰을 CSS custom properties로 구현한다.
- 서버 상태는 TanStack Query, 짧은 UI 상태만 Zustand 또는 컴포넌트 state로 관리한다.
- 결과 canvas와 동일한 내용을 DOM 목록으로 제공한다.
- loading, empty, partial, error, denied, success 상태를 기능별 테스트 fixture로 만든다.
- 1280×720, 1024px 전환, 320 CSS px와 200% 확대를 검증한다.

## 10. 마이그레이션·롤백·업데이트

- 앱 시작 전 DB와 index manifest를 같은 버전 백업으로 스냅샷한다.
- Alembic migration은 forward-only이며 실패하면 앱을 열지 않고 이전 실행 파일과 스냅샷 복구 안내를 표시한다.
- 모델·인덱스 변경은 새 version namespace에 구축한 뒤 pointer를 원자적으로 전환한다.
- 설치 업그레이드는 사용자 데이터 폴더를 삭제하지 않는다.
- rollback 가능성은 Windows E2E에서 이전 버전 설치→데이터 생성→업그레이드→복원 순서로 검증한다.

## 11. 운영·백업·관찰성

- 구조화 로그는 request_id, job_id, stage, duration_ms, error_code만 기록한다.
- 로컬 health endpoint는 DB·파일·index·모델 가용성을 구분한다.
- 진단 번들은 사용자가 직접 내보내며 외부로 자동 전송하지 않는다.
- 백업은 수동 생성이 MVP 범위이며 복원 전에 충돌 미리보기를 제공한다.
- 실제 데이터 보관 기간은 Product Owner가 파일럿 반입 전 확정한다.

## 12. 리뷰와 완료 정의

각 작업은 실패 테스트→최소 구현→테스트 통과→리팩터링→diff 검토→작은 커밋 순서를 따른다.

완료 조건:

- 관련 FR/FN/TC가 커밋 또는 PR 설명에 연결된다.
- 단위·통합 테스트와 타입·lint가 통과한다.
- 파일·좌표·단위의 실패 fixture가 추가된다.
- 보안·개인정보·접근성 영향이 검토된다.
- 사용자 문서와 migration이 동작 변경을 반영한다.
- Gate 결과가 미달이면 완료로 표시하지 않는다.

```text
역할: <해당 Task의 엔지니어 역할>
```
