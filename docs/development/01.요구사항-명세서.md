## 1. 목적과 문제

기계·설비 및 전기·계장 설계자는 과거 Excel 오류 사례와 사내 경험을 바탕으로 PDF/DXF 도면을 수작업 검토한다. 사례가 텍스트·표·이미지로 분산돼 검색과 재사용이 어렵고, 검토 품질이 개인 경험에 좌우된다. 본 제품은 원본 추적이 가능한 지식과 승인 규칙을 구축하고 설계자가 도면을 자체 점검하도록 돕는다.

## 2. 목표와 성공 기준

| ID | 업무 요구사항 |
| --- | --- |
| BR-001 | 설계자가 제출 전에 핵심 도면 오류를 로컬 PC에서 발견할 수 있어야 한다. |
| BR-002 | 모든 판정은 규칙·사례·도면 위치로 추적 가능해야 한다. |
| BR-003 | 오류 사례에서 파생된 규칙은 사람 승인과 버전 이력을 거쳐야 한다. |
| BR-004 | 원본은 기본적으로 PC 밖으로 나가지 않으며 외부 AI 사용은 명시적 동의가 필요하다. |

성공은 추출 성공률 95% 이상, 승인 규칙 정밀도 90% 이상, 주요 오류 재현율 80% 이상, 유사 사례 Top-5 적중률 80% 이상, 기준 도면 전체 분석 3분 이내로 측정한다.

## 3. 사용자와 이해관계자

| 역할 | 책임 |
| --- | --- |
| 설계자 | 지식 가져오기, 규칙 검토, 도면 검사, 결과 판단과 내보내기 |
| Product Owner | 범위, 업무 규칙, 외부 전송과 출시 승인 |
| Technical Lead | 아키텍처, 모델, 보안, 패키징과 운영 결정 |
| QA Lead | 골든셋, 테스트, 품질 Gate와 접근성 검토 |

MVP 애플리케이션에는 로그인이나 역할별 권한 기능을 구현하지 않는다. 위 역할은 문서와 개발 거버넌스를 위한 책임 구분이다.

## 4. 시스템 경계

### MVP 포함

- 부분 표준화 Excel의 텍스트·표·임베디드 이미지 가져오기
- 규칙 후보 추출, 승인·비활성 및 변경 이력
- PDF/DXF 입력 검증, 정형 추출, OCR, 좌표 정규화
- 치수·공차, 재질·규격·부품번호, 레이어·선종·축척·양식 검사
- 텍스트·Pixel RAG, 근거 기반 로컬 개선 제안
- 웹 하이라이트와 Excel/CSV 내보내기
- 데이터 삭제, 암호화 백업·복원, 진단 번들
- CPU 기본, GPU 가속, 명시적 OpenAI 보완 프로파일

### MVP 이후

- 중앙 서버, 계정, 팀 협업과 결재
- DWG 직접 지원, 3D CAD, 감시 폴더
- PDF 보고서, 수정 전후 비교, 장기 통계

### 명시적 제외

- 도면 자동 수정과 최종 설계 승인
- 근거 없는 AI 오류 확정
- 사용자 동의 없는 외부 데이터 전송

## 5. 기능 요구사항

| ID | 우선순위 | 요구사항 | 수용 기준 |
| --- | --- | --- | --- |
| FR-001 | Must | Excel 가져오기 전에 시트·열·이미지 앵커·주변 문맥을 미리 보여주고 수정할 수 있어야 한다. | 사용자가 확정하기 전 DB·벡터 인덱스에 반영되지 않는다. |
| FR-002 | Must | 확정한 매핑으로 지식 사례를 멱등하게 저장하고 가져오기 프로파일을 재사용해야 한다. | 같은 파일·프로파일 재실행 시 중복 사례가 생기지 않는다. |
| FR-003 | Must | 규칙 후보를 `draft → approved → inactive`로 관리하고 출처·단위·예외·심각도·버전을 보존해야 한다. | 잘못된 상태 전이는 거부되고 승인 이력이 조회된다. |
| FR-004 | Must | `.xlsx`, `.pdf`, `.dxf`만 허용하고 암호화·서명 불일치·크기 초과 파일을 사유와 함께 거부해야 한다. | XLSX 100MB, PDF 200MB·100페이지, DXF 100MB 상한이 적용된다. |
| FR-005 | Must | PDF에서 벡터 텍스트·좌표를 추출하고 스캔 페이지는 OCR과 1024px·25% 겹침 타일로 처리해야 한다. | 저해상도 페이지는 `정보 부족`으로 표시된다. |
| FR-006 | Must | DXF에서 modelspace/paperspace, 레이어, 주요 엔티티, 치수, 블록과 CAD↔픽셀 좌표를 추출해야 한다. | 누락 XREF·필수 폰트는 규칙 평가를 차단한다. |
| FR-007 | Must | 승인 규칙으로 세 검사군을 결정론적으로 평가해야 한다. | 승인되지 않은 규칙은 `위반`을 만들지 않는다. |
| FR-008 | Must | 사례 텍스트를 키워드·벡터 혼합 방식으로 Top-5 검색해야 한다. | 분야·오류 유형 필터와 출처 셀이 결과에 포함된다. |
| FR-009 | Must | 사례 이미지와 도면 타일을 Pixel RAG로 비교하고 시각 근거 좌표를 보존해야 한다. | 텍스트 점수와 시각 점수를 별도로 제공한다. |
| FR-010 | Must | 분석을 단계별 영속 작업으로 실행하고 한 번에 한 작업만 처리해야 한다. | 취소, 재시작, 실패 단계 재시도가 가능하다. |
| FR-011 | Must | 결과 화면에서 상태·심각도·신뢰도·위치·규칙·사례를 함께 보여줘야 한다. | 하이라이트 선택 시 근거와 원본 위치가 연결된다. |
| FR-012 | Must | 근거를 사용해 문제·확인 위치·수정 방법·추가 조건을 한국어로 제안해야 한다. | 근거가 없으면 수정 지시 대신 확인 질문을 반환한다. |
| FR-013 | Must | 정해진 열 순서로 XLSX와 UTF-8 BOM CSV를 내보내야 한다. | 상태, 심각도, 유형, 좌표, 규칙, 사례, 제안, 신뢰도, 메모가 포함된다. |
| FR-014 | Must | 지식·규칙·프로파일을 암호화 백업하고 복원해야 한다. | Argon2id와 AES-256-GCM을 사용하며 원본 포함은 선택 사항이다. |
| FR-015 | Must | 하드웨어를 감지해 CPU/GPU 프로파일을 추천하고 모델 설치·OpenAI 설정을 관리해야 한다. | 모델이 없어도 규칙 검사만 실행된다. |
| FR-016 | Must | 프로젝트 완전 삭제와 비식별 진단 번들 생성을 지원해야 한다. | DB·벡터·파일이 제거되고 진단에 원문·키·절대 경로가 없다. |

## 6. 업무 규칙

| ID | 규칙 |
| --- | --- |
| RULE-001 | 결과 상태는 `violation`, `suspected`, `insufficient_information` 중 하나다. |
| RULE-002 | `approved` 규칙만 `violation`을 생성한다. |
| RULE-003 | 검색·AI는 규칙 결과를 취소하거나 심각도를 자동 변경하지 않는다. |
| RULE-004 | 단위를 확정할 수 없거나 호환되지 않으면 자동 위반 대신 `insufficient_information`을 생성한다. |
| RULE-005 | 심각도와 신뢰도는 독립 값이며 심각도는 사람이 규칙에 지정한다. |
| RULE-006 | 분석은 PC당 하나만 실행하며 추가 요청은 FIFO 대기한다. |
| RULE-007 | OpenAI 호출은 기본 비활성이고 전송 미리보기와 건별 동의가 있어야 한다. |
| RULE-008 | 프로젝트 삭제는 원본, 타일, 벡터, 결과와 작업 상태를 함께 제거한다. |
| RULE-009 | 지식·규칙·파서·모델·프롬프트·인덱스 버전은 분석 결과와 함께 보존한다. |

| NFR-010 | 초기 지식 규모인 Excel 10개·오류 사례 1천 건에서 가져오기와 Top-5 검색이 기능 저하 없이 동작해야 한다. | 용량 fixture 가져오기와 검색 p95 측정 |

## 8. 데이터·보존·보안

- 원본 Excel과 도면의 업무 소유자는 이를 제공한 조직이며, 로컬 설계자는 해당 PC의 데이터 관리 책임을 가진다.
- Product Owner는 필드 의미·규칙·분류의 업무 책임자이고 Technical Lead는 저장·삭제·백업 구현 책임자다.
- 앱 데이터 루트는 `%LOCALAPPDATA%\DevPreReview`다.
- 사용자가 삭제하기 전까지 보관하되 실제 회사 데이터의 세부 보관 기간은 Product Owner가 파일럿 반입 전 확정한다.
- 원본과 파생물은 해시 기반 경로를 사용하며 로그에는 논리 ID만 기록한다.
- 실제 회사 도면은 소스 저장소와 테스트 fixture에 넣지 않는다.
- OpenAI 보완 실패나 동의 철회 시 로컬 결과를 보존하고 전송 payload는 메모리에서 폐기한다.

## 9. 전제와 의존성

- 대표 Excel 3종, 오류 사례 100건 이상, PDF 10건, DXF 10건, 전문가 표기 오류 50건 이상을 확보한다.
- 모델 artifact와 라이선스는 M3 전 Technical Lead가 확정한다.
- 최종 평가 자료는 튜닝 자료와 분리하며 QA Lead가 접근을 관리한다.
- 설치 파일 코드 서명은 MVP 패키징 전에 별도 조달한다.
