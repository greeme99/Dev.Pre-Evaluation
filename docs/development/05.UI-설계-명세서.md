## 1. 디자인 기준

현재 저장소에는 기존 제품 UI나 디자인 시스템이 없다. 이 문서가 MVP의 최초 디자인 기준이며, 실제 구현에서 토큰을 변경하려면 접근성 확인과 Product Owner 검토가 필요하다. 이번 산출물에는 고해상도 시안과 HTML 프로토타입이 포함되지 않는다.

## 2. 사용자와 디자인 개념

- **사용자:** 도면과 표를 오랫동안 비교하는 기계·전기 설계자.
- **핵심 작업:** 오류를 빨리 많이 보여주는 것보다 근거와 위치를 확실히 확인하는 것.
- **개념:** “검토 데스크.” 화면은 차분하고 고밀도이며, 판정 종류와 처리 출처를 명확히 구분한다.
- **피해야 할 표현:** AI가 확정한 듯한 문구, 과도한 애니메이션, 근거 없는 성공 색상, 장식적 그라데이션.

## 3. 디자인 토큰

### 색상

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-bg` | `#F5F7F9` | 앱 배경 |
| `--color-surface` | `#FFFFFF` | 패널·카드 |
| `--color-text` | `#17202A` | 본문 |
| `--color-muted` | `#52606D` | 보조 정보 |
| `--color-border` | `#CBD5E1` | 경계 |
| `--color-primary` | `#1457D9` | 주요 action·focus 보조 |
| `--color-violation` | `#B42318` | 위반 |
| `--color-suspected` | `#B54708` | 의심 |
| `--color-insufficient` | `#475467` | 정보 부족 |
| `--color-success` | `#067647` | 성공 |
| `--color-focus` | `#7C3AED` | 2px focus ring |

색은 상태의 유일한 전달 수단이 아니다. 상태명, 아이콘 모양, 하이라이트 패턴을 함께 사용한다. 모든 텍스트 대비는 WCAG 2.2 AA를 충족한다.

### 타이포그래피와 간격

- UI 글꼴: `Pretendard`, `Noto Sans KR`, `Segoe UI`, sans-serif 순서.
- 코드·도면 식별자: `Cascadia Mono`, `Consolas`, monospace.
- 기본 본문 14px/1.5, 표 13px/1.45, H1 24px, H2 18px, H3 16px.
- 간격 배수: 4, 8, 12, 16, 24, 32px.
- 둥근 모서리: 입력·버튼 6px, 패널 8px. 그림자는 모달과 떠 있는 메뉴에만 사용한다.

### 밀도와 크기

- 기본 컨트롤 높이 36px, 고밀도 표 행 36px, 주요 버튼 40px.
- 클릭·터치 target은 최소 24×24 CSS px, 좁은 화면에서는 44×44px을 권장한다.
- 도면 결과 화면은 목록 280px, 근거 패널 360px, 중앙 뷰어 가변 폭을 기본으로 한다.

## 4. 컴포넌트 규칙

| 컴포넌트 | 규칙 |
| --- | --- |
| Button | Primary는 화면당 하나, 파괴적 action은 Danger와 확인 설명 사용 |
| StatusBadge | 위반·의심·정보 부족의 텍스트와 아이콘 포함 |
| DataTable | 정렬 상태, 행 선택, 키보드 이동, sticky header, 빈 상태 제공 |
| FileDropzone | click과 drag가 동일하며 허용 형식·상한을 상시 표시 |
| ProgressStepper | 완료·현재·대기·실패를 텍스트로 표시하고 단계 시간 제공 |
| EvidenceCard | 근거 종류, ID, 출처 위치, 점수, 원본 이동 action 포함 |
| DrawingViewer | 확대·이동·영역 맞춤, 패턴 하이라이트, 텍스트 좌표 대체 제공 |
| Dialog | 제목, 설명, 초기 focus, focus trap, Escape, focus return 필수 |
| Toast | 저장 성공 등 비차단 피드백만; 오류 해결 정보는 화면 안에 유지 |
| InlineError | 문제·영향·해결·재시도 action을 가까운 위치에 표시 |

## 5. 상태 표현

- **Loading:** skeleton은 구조가 정해진 영역만 사용하고 실제 단계가 있으면 ProgressStepper를 사용한다.
- **Empty:** 왜 비었는지와 다음 action을 제공한다. 결과 없음은 “오류 없음 보증”으로 표현하지 않는다.
- **Error:** 기술 예외 대신 오류 코드, 사용자 영향, 해결, 재시도 가능 여부를 제공한다.
- **Denied:** 형식·암호화·외부 동의 등 정책 차단 사유를 정확히 설명한다.
- **Success:** 생성·갱신·건너뜀 수와 다음 이동을 보여준다.
- **Partial:** 규칙 결과가 준비되고 검색 중이면 준비된 범위를 표시한다.
- **Offline:** 규칙 검사 가능 여부와 모델/외부 기능 제한을 구분한다.

## 6. 접근성

- 키보드 focus 순서는 시각 순서와 같고 모든 action에 visible focus가 있다.
- 진행률 live region은 퍼센트마다 알리지 않고 단계 전환과 실패만 알린다.
- 도면 canvas의 선택 결과는 동일 정보를 가진 DOM 목록과 연결한다.
- 표 머리글, 정렬, 선택 상태와 오류 셀을 보조기술에 제공한다.
- 모달 focus trap, 닫기 후 focus 복귀, reduced-motion을 지원한다.
- 200% 확대와 320 CSS px reflow를 검증한다.
- 아이콘 단독 버튼은 한국어 accessible name과 tooltip을 가진다.

## 7. 콘텐츠 원칙

- 판정 문구: “오류 확정” 대신 `위반`, `의심`, `정보 부족`을 그대로 사용한다.
- 개선 제안은 명령형보다 “확인 후 …로 수정”처럼 조건을 포함한다.
- 파일 거부 메시지는 “지원하지 않음”에서 끝내지 않고 변환·복구 방법을 제시한다.
- 신뢰도는 백분율과 근거 품질 설명을 함께 표시하며 심각도 옆에 혼합하지 않는다.
- 예시 데이터는 “가상 예시”로 표시하고 실제 회사명·도면번호를 사용하지 않는다.

## 8. 도면 시각화

- 위반은 실선 사각형+번호, 의심은 점선+번호, 정보 부족은 사선 패턴+번호로 표시한다.
- 같은 영역의 여러 결과는 번호 스택과 목록 그룹으로 표현한다.
- PDF page bbox와 DXF entity handle/cad_bbox를 상세 패널에서 복사할 수 있다.
- 확대해도 선 두께와 번호가 읽히도록 screen-space overlay를 사용한다.

## 9. 테마와 자산

- MVP는 밝은 테마 하나만 제공한다. 운영체제 고대비 모드는 존중한다.
- 아이콘은 번들되는 오픈소스 SVG 세트 하나로 제한하고 라이선스를 기록한다.
- 외부 CDN, 웹폰트, 원격 이미지에 의존하지 않는다.
- 로고는 제품명이 텍스트로 표시되는 wordmark로 시작하며 별도 자산 결정은 MVP 이후다.
