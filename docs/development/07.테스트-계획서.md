## 1. 테스트 상태와 목적

이 문서는 출시 판정을 위해 향후 실행할 테스트 계획이다. 제품 코드와 개발환경 단위·컴포넌트 테스트는 존재하지만, 아래 TC는 요구된 환경·데이터·절차로 수행한 별도 실행 보고서가 없으므로 모두 **미실행(Not Run)**이다. 개발 테스트 통과나 평가 하네스 스모크를 이 표의 “통과”로 해석하지 않는다.

## 2. 범위와 환경

- 기능: FN-001~FN-010, FR-001~FR-016, RULE-001~RULE-009.
- 비기능: NFR-001~NFR-009.
- 용량: NFR-010의 Excel 10개·오류 사례 1천 건.
- 기준 OS: Windows 10/11 x64.
- 기준 성능 PC: 8코어 CPU, RAM 16GB, GPU 없음. 최종 모델은 QA Lead가 M4 종료 전에 확정한다.
- 브라우저: 패키지 실행 시점의 최신 Chrome·Edge 안정 버전과 WebView가 아닌 기본 브라우저.
- 데이터: 합성/비식별 fixture와 별도 암호화 골든셋. 실제 회사 도면은 저장소나 CI에 넣지 않는다.

## 7. 상태·경계·실패 매트릭스

반드시 다음 조합을 기능별로 적용한다.

- 정상, 빈 입력, 최소·최대 경계, 한 단계 초과.
- 잘못된 형식, 암호화, 손상, 중복, 재시도, 취소.
- 앱 재시작, 디스크 부족, 모델 없음, 네트워크 없음, 외부 실패.
- queued/running/cancelling/cancelled/failed/completed 모든 전이.
- draft/approved/inactive 정상 전이와 잘못된 전이 거부.
- loading/empty/partial/error/denied/success UI 상태.
- 삭제·복원·외부 전송 같은 위험 동작의 확인과 실패 복구.

## 8. 테스트 데이터

- `tests/fixtures`: 합성·비식별 최소 파일만 커밋한다.
- 골든셋 최소 구성: 대표 Excel 3종, 사례 100건, PDF 10건, DXF 10건, 전문가 표기 오류 50건.
- `tuning`과 `final` 분할은 파일 해시로 고정하며 final은 튜닝에 사용하지 않는다.
- 가상 회사·도면번호를 사용하고 실제 비밀·주소·고객 식별자를 복사하지 않는다.
- 손상·암호화 fixture는 생성 절차를 스크립트로 보존한다.

## 9. UAT

Product Owner와 대표 설계자가 다음을 수행한다.

1. 실제와 구조가 같은 비식별 Excel을 미리보기·수정·확정한다.
2. 규칙 후보를 검토해 승인·비활성한다.
3. 기계 PDF와 전기 DXF를 검사한다.
4. 위반·의심·정보 부족의 의미와 근거를 구별한다.
5. 잘못된 제안을 기각하고 검토 메모를 내보낸다.
6. 백업 후 새 Windows 사용자 환경에서 복원한다.

UAT 완료 기준은 blocker 0, critical 0, Must 흐름 완료, 오해를 부르는 판정 문구 0이다.

## 11. 출시 Gate

- Must TC-001~TC-033 통과, blocker/critical 0.
- TC-101~TC-110 기준 충족.
- 골든셋과 성능 보고서에 앱·모델·파서·규칙·인덱스 버전 기록.
- SBOM, 라이선스, 설치 파일 SHA-256과 Windows VM E2E 증거 제공.
- OpenAI 보완을 켜지 않은 상태의 outbound 요청 0건.
- Product Owner, Technical Lead, QA Lead 승인.

## 12. 미래 테스트 결과 보고서 구조

실행 시 별도 보고서에 build ID, 환경, 데이터 manifest hash, 실행 시각, TC별 Pass/Fail/Blocked, 결함 링크, 지표 원자료, 잔여 위험과 승인자를 기록한다. 이 계획 문서의 상태를 실행 결과로 덮어쓰지 않는다.
